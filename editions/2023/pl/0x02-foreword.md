# Przedmowa

Podstawowym elementem innowacji w dzisiejszym świecie napędzanym przez
aplikacje jest interfejs programowania aplikacji (Application Programming
Interface, API). API stanowią kluczową część nowoczesnych aplikacji mobilnych,
SaaS i webowych w wielu dziedzinach, od bankowości, handlu detalicznego
i transportu po IoT, pojazdy autonomiczne i inteligentne miasta. Można je
znaleźć w aplikacjach skierowanych do klientów, skierowanych do partnerów oraz
w aplikacjach wewnętrznych.

Z natury API udostępniają logikę aplikacji oraz dane wrażliwe, takie jak dane
osobowe umożliwiające identyfikację (Personally Identifiable Information, PII),
i właśnie dlatego coraz częściej stają się celem atakujących. Bez bezpiecznych
API szybkie innowacje byłyby niemożliwe.

Choć szersza lista Top 10 ryzyk bezpieczeństwa aplikacji webowych nadal ma
sens, szczególny charakter API sprawia, że potrzebna jest lista ryzyk
bezpieczeństwa specyficznych dla API. Bezpieczeństwo API koncentruje się na
strategiach i rozwiązaniach służących zrozumieniu i ograniczaniu unikalnych
podatności oraz ryzyk bezpieczeństwa związanych z API.

Jeśli znasz [projekt OWASP Top 10][1], zauważysz podobieństwa między oboma
dokumentami: oba zostały przygotowane z myślą o czytelności i łatwości
wdrożenia. Jeśli dopiero zaczynasz przygodę z serią OWASP Top 10, lepiej będzie
najpierw przeczytać sekcje [Ryzyka bezpieczeństwa API][2] oraz [Metodologia
i dane][3], a dopiero potem przejść do listy Top 10.

Możesz wnieść swój wkład w OWASP API Security Top 10, zgłaszając pytania,
komentarze i pomysły w repozytorium projektu na GitHubie:

* https://owasp.org/www-project-api-security/
* https://github.com/OWASP/API-Security/blob/master/CONTRIBUTING.md
