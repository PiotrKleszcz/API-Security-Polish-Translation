# Wprowadzenie

## Witamy w OWASP API Security Top 10 - 2023!

Witamy w drugiej edycji OWASP API Security Top 10!

Ten dokument, którego celem jest podnoszenie świadomości, został po raz
pierwszy opublikowany w 2019 roku. Od tego czasu branża bezpieczeństwa API
rozkwitła i dojrzała. Jesteśmy przekonani, że ta praca miała na nią pozytywny
wpływ, ponieważ szybko została przyjęta jako branżowy punkt odniesienia.

API odgrywają bardzo ważną rolę we współczesnej architekturze aplikacji.
Ponieważ jednak innowacje postępują w innym tempie niż budowanie świadomości
w zakresie bezpieczeństwa, uważamy, że ważne jest skupienie się na podnoszeniu
świadomości na temat typowych słabych punktów bezpieczeństwa API.

Głównym celem OWASP API Security Top 10 jest edukowanie osób zaangażowanych
w tworzenie i utrzymanie API, na przykład programistów, projektantów,
architektów, menedżerów czy całych organizacji. Więcej informacji o projekcie
API Security znajdziesz na [stronie projektu][1].

Jeśli nie znasz serii OWASP Top 10, zalecamy zapoznanie się co najmniej
z następującymi projektami Top 10:

* [OWASP Cloud-Native Application Security Top 10][2]
* [OWASP Desktop App Security Top 10][3]
* [OWASP Docker Top 10][4]
* [OWASP Low-Code/No-Code Top 10][5]
* [OWASP Machine Learning Security Top Ten][6]
* [OWASP Mobile Top 10][7]
* [OWASP TOP 10][8]
* [OWASP Top 10 CI/CD Security Risks][9]
* [OWASP Top 10 Client-Side Security Risks][10]
* [OWASP Top 10 Privacy Risks][11]
* [OWASP Serverless Top 10][12]

Żaden z tych projektów nie zastępuje innego: jeśli pracujesz nad aplikacją
mobilną korzystającą z API działającego na backendzie, lepiej przeczytać obie
odpowiednie listy Top 10. To samo dotyczy pracy nad aplikacją webową lub
desktopową korzystającą z API.

W sekcji [Metodologia i dane][13] możesz przeczytać więcej o tym, jak powstała
ta edycja. Tymczasem zachęcamy wszystkich do dzielenia się pytaniami,
komentarzami i pomysłami w naszym [repozytorium na GitHubie][14] lub na
[liście mailingowej][15].
